# 소득 공백 재무설계 데모 (Rust 확장 모형)

CPA 2차 유예생인 가상 고객이 **합격 발표부터 첫 급여까지 생기는 소득 공백**을 견딜 수 있는지 계산하는 로컬 웹 데모입니다. 고객 정보와 금액은 모두 합성 데이터이며, 합격·채용·수익을 예측하거나 보장하지 않습니다.

| 요약 | 내용 |
|---|---|
| 무엇을 보여 주나 | 네 전략(A 전업 수험, B 근로 병행, C 취업 전환, D 조건부 전환)의 18개월 잔액·안전자금 검사, 60개월 현재가치, 지연 민감도, AI 원출력 검증, 실행 계획과 보고서 |
| 계산 | Rust 백엔드가 입력값으로 결정론적으로 계산합니다. 프런트는 결과를 표시만 합니다 |
| AI 키 | **필요 없습니다.** 키가 없으면 규칙 기반 답변과 Rust 계산만 동작합니다 |
| 실행 형태 | 백엔드 API(127.0.0.1:8080)와 프런트 개발 서버(127.0.0.1:5173)를 함께 띄우는 로컬 데모입니다. 공개 배포용 서비스가 아닙니다 |

## 두 모형의 차이

이 데모는 참가작 본문의 **Python v4 참조 모형과 다른 가정을 쓰는 별도 확장 모형**입니다. 두 결과를 같은 조건의 독립 검산으로 보거나 숫자를 그대로 비교하지 마세요.

| 구분 | 본문 참조 모형(Python v4) | 이 데모(Rust) |
|---|---|---|
| 금액 단위 | 만원 | 원 |
| 안전자금 하한 | 시점별 420 → 375 → 360만원 | 기본 고정 360만원 |
| 일반직 / CPA 급여 | 230만원(연 3% 성장) / 290만원(연 5% 성장) | 270만원 고정 / 수습 320만원, 12개월 후 410만원 |
| B 시간제 첫 소득 | 2027.02 | 2026.12 |
| C 첫 급여 | 2027.04 | 2027.02 |
| D 전략 | 고정된 전환 일정 | 잔액 신호(720만원, 480만원 이하)에 따른 전환 |
| 가중치 | p=0.60, q=0.70, B 감소폭 0.10 | p=0.45, q=0.70, 감소폭 0.05 |
| 할인 방식 | 유효 월 할인율 | 연율을 12로 나눈 월율 |
| 60개월 지표 | 초기 현금 포함 | 초기 현금 제외 |

## 화면

| 경로 | 화면 | 키 없이 동작하는 내용 |
|---|---|---|
| `/` | 홈 | 고객 상황과 핵심 결과 요약 |
| `/client` | 고객 정보 | 입력 변경 → "적용하고 다시 계산" → 전 화면 재계산, "기본값 복원" |
| `/canvas` | AI 분석 | 입력·계산·검증·실행 규칙의 연결과 각 카드의 출처 표시 |
| `/copilot` | AI 상담 | 추천 질문 6개에 Rust 계산 기반 규칙 답변. 직접 입력한 질문과 문장 다듬기는 키가 있어야 함 |
| `/simulator` | 시뮬레이션 | 전략별 18개월 경로, 합격 후 지연, 60개월 가치 비교 |
| `/verification` | AI 검증 | 기록된 AI 원출력 8건(E1~E8, 주장 23개)을 엔진 계산·공식 자료와 대조. 새 AI 호출은 하지 않음 |
| `/plan` | 실행 계획 | 잔액 신호에 따른 전환 규칙과 월별 점검 |
| `/report` | 보고서 | 현재 입력과 계산 결과를 묶은 보고서, 브라우저 인쇄·PDF 저장 |

검증 화면의 "계산 일치·오류 발견·검토 필요"는 **엔진과 규칙의 자동 대조 결과**입니다. 사람의 최종 금융 판정이 아니며, 화면의 "AI 1차 검토 의견"도 판정이 아닙니다. 사람의 판정은 화면에서 근거를 적어 기록할 때만 바뀝니다(브라우저 저장소).

## 준비물

- **Node.js 22 LTS**(검증 버전 22.23.5). Windows의 Node.js 24에서 프런트 도구가 비정상 종료된 기록이 있어 22를 권장합니다.
- **Rust stable**(검증 버전 1.100.0, `x86_64-pc-windows-msvc`). Windows에서는 Visual Studio C++ Build Tools가 필요합니다.
- 인터넷: `npm ci`·`cargo` 의존성 설치에 필요합니다. 실행 중에는 글꼴(Google Fonts, jsDelivr의 Pretendard)만 외부에서 불러오며, 연결이 없으면 시스템 글꼴로 대체됩니다.

## 실행 — 터미널 두 개

**터미널 1 — 백엔드** (이 폴더에서 시작)

```powershell
cd backend
cargo run --locked
```

Windows에서 `link.exe`를 찾지 못하면 이 폴더에서 `scripts\development\cargo-msvc.cmd run --locked`를 실행합니다. MSVC 환경을 잡은 뒤 `backend`에서 cargo를 실행합니다.

**터미널 2 — 프런트엔드** (이 폴더에서 시작)

```powershell
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --strictPort
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. 개발 서버가 `/api` 요청을 `http://localhost:8080`으로 넘깁니다(다른 주소면 환경변수 `FINOVA_API`로 지정). 백엔드 상태는 `http://127.0.0.1:8080/api/health`에서 확인합니다. `ai.mode`가 `rule_based`이면 키 없이 실행 중입니다.

## 데이터와 설정

- 백엔드는 `backend` 폴더를 기준으로 `../topics`, `../data`, `../ai`를 읽습니다. 세 폴더는 실행에 필요합니다. 경로를 바꾸려면 `FINOVA_TOPICS_DIR`, `FINOVA_DATA_DIR`, `FINOVA_AI_DIR`을 지정합니다.
- 첫 실행 때 `backend/finova.db`(SQLite)를 만들고 합성 데이터를 넣습니다. 다른 위치를 쓰려면 `DATABASE_URL`을 지정합니다. DB 파일은 Git에서 제외됩니다.
- `.env`는 필요 없습니다. 쓰려면 `.env.example`을 복사합니다. 백엔드는 이 폴더의 `.env`를 자동으로 읽으며, 그 안의 `GEMINI_*` 값이 OS 환경변수보다 우선합니다. **키 없이 실행하려면 `GEMINI_API_KEY`를 비워 두세요.** 키는 서버에서만 쓰이며 프런트에 넣지 않습니다.
- 서버는 127.0.0.1에만 바인딩합니다. 개발 모드의 관리자 토큰은 로컬 데모용 기본값이므로 외부에 노출하지 않습니다. 사용자 인증이 없으니 터널이나 외부 배포에 그대로 쓰지 마세요.

## 검사

```powershell
# frontend
npm run lint
npm run typecheck
npm test
npm run build

# backend
cargo test --locked

# 백엔드 실행 중일 때 API 스모크 검사(이 폴더에서)
.\scripts\validation\smoke.ps1 -Base http://127.0.0.1:8080
```

이 분리본에서 실제로 확인한 결과: Node 22.23.5에서 lint·typecheck·테스트 3개·빌드 통과, Rust `cargo test --locked` 78개(단위 56·API 22) 통과, 스모크 6/6 통과. 브라우저에서 8개 화면, 입력 변경 후 재계산과 기본값 복원을 확인했습니다. 모두 AI 키가 없는 상태에서 실행했습니다.

## 폴더

| 폴더 | 역할 |
|---|---|
| `frontend/` | React 18 · TypeScript · Vite 6 화면 |
| `backend/` | Rust · Axum · SQLx(SQLite) API와 계산 엔진, 테스트 |
| `ai/` | 에이전트 설정·프롬프트, AI 검증 실험 정의(`prompts/verification/cpa_experiments.json`)와 기록된 원출력(`evaluations/cpa_experiment_runs.json`) |
| `topics/` | 주제별 화면·규칙 설정 |
| `data/` | 합성 고객·목표·시나리오 시드 데이터 |
| `docs/` | API 명세, 구조, Rust 모형 가정, AI 검증 기준, 디자인·글꼴 출처 |
| `scripts/` | Windows MSVC 래퍼, 동시 실행, 최초 설정, 합성 데이터 재생성, 스모크 검사 |

코드·변수 이름에 남은 `FINOVA`는 원본 데모의 작업 이름입니다. 출처와 제3자 자산은 [NOTICE.md](NOTICE.md)를 확인하세요.
